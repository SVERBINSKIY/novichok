# Новичок

Демо-сервис адаптации сотрудников в первые 90 дней. В нём есть персональные опросы, рабочее место HR и сводная аналитика для руководителя.

> **Важно:** приложение сейчас предназначено для демонстрации. Имена, ответы и аналитические закономерности искусственные. Не используйте его для реальных сотрудников или персональных данных.

## Возможности

- Опросы новичка по персональной ссылке.
- Очередь сигналов и карточки сотрудников для HR.
- Перенос стандартного опроса на другую дату и копирование приглашения сотруднику.
- Сводная аналитика для руководителя без имён и индивидуальных ответов.
- Синтетические демо-данные для знакомства с интерфейсом.

## Требования

- Node.js 20 или новее.
- npm (устанавливается вместе с Node.js).

## Запуск на своём компьютере

Откройте терминал в папке проекта и выполните:

```sh
npm install
cp .env.example .env
npm run build
npm start
```

Откройте в браузере <http://localhost:3000>. Чтобы остановить сервер, нажмите `Ctrl+C` в терминале.

При необходимости измените параметры в `.env`. Для обычного знакомства с демо оставьте `DEMO_MODE=true`. Файл `.env` содержит локальные настройки и секреты: не добавляйте его в Git и не отправляйте в GitHub.

### Настройки

| Переменная | Назначение |
|---|---|
| `PORT` | Порт сервера; по умолчанию `3000` |
| `HR_PASSWORD` | Пароль HR при выключенном демо-входе |
| `BOSS_PASSWORD` | Пароль руководителя при выключенном демо-входе |
| `DEMO_MODE` | `true` включает демонстрационный вход и сброс демо-данных |
| `SESSION_SECRET` | Секрет сессии; для опубликованного сервиса задайте длинное случайное значение |
| `DB_FILE` | Необязательный путь к файлу SQLite |

Для локальной разработки с паролями установите `DEMO_MODE=false` и задайте `HR_PASSWORD` и `BOSS_PASSWORD`. На демо-режим пароль не требуется.

## Инструкция: как пользоваться сервисом

### Новичок

1. На главной странице выберите имя в карточке «Посмотреть как новичок». Это синтетический персонаж, а не реальный сотрудник.
2. На странице опроса прочитайте, за кого вы отвечаете, и нажмите «Начать».
3. Ответьте на вопросы и нажмите «Отправить». Если ответы показывают, что есть трудность, появится вопрос о том, что мешает. Опрос не является экзаменом или оценкой сотрудника.

### HR

1. На главной странице нажмите «Посмотреть как HR». Для демо пароль не нужен.
2. На вкладке «Сегодня» посмотрите, кому требуется внимание. Нажмите на имя, чтобы открыть карточку сотрудника.
3. Чтобы посмотреть ответы, найдите сотрудника во вкладке «Все новички» и нажмите на его строку.
4. Чтобы назначить опрос, в карточке сотрудника выберите блок «Назначить готовый опрос». Выберите ещё не пройденный опрос и дату доступности, затем нажмите «Назначить».
5. Нажмите «Скопировать приглашение» и самостоятельно отправьте скопированный текст сотруднику. Ссылка персональная; сервис не рассылает её автоматически.
6. После разговора с сотрудником вернитесь во вкладку «Сегодня», выберите «Позвонить» или «Заметка», заполните нужные поля и сохраните действие.
7. Во вкладке «Ожидают ответа» видны просроченные опросы; для напоминания можно скопировать ссылку.
8. Чтобы добавить сотрудника, нажмите «Добавить новичка» на вкладке «Сегодня» или «Все новички» и заполните карточку. После сохранения система подготовит персональную ссылку и стандартные опросы.

HR может переносить готовые опросы, но не может создавать собственные вопросы. Стандартные опросы запланированы на 3-й, 14-й, 30-й, 60-й и 85-й день после даты выхода; вопросы меняются в зависимости от этапа адаптации.

### Руководитель

1. На главной странице нажмите «Посмотреть как руководитель». Для демо пароль не нужен.
2. На дашборде просматривайте общие показатели, удержание, причины и точки внимания.
3. Переключайте разрез удержания по подразделениям и точкам. Имена и индивидуальные ответы не показываются; небольшие группы скрываются.

### Сброс демо

Кнопка «Сбросить демо-данные» на главной странице восстанавливает исходные синтетические записи и удаляет изменения, сделанные во время демонстрации.

## Проверки проекта

```sh
npm test
npm run smoke
npm run seed
```

- `npm test` запускает модульные тесты правил риска и метрик.
- `npm run smoke` проверяет основные API-сценарии, включая назначение опроса HR.
- `npm run seed` заново создаёт синтетические данные и удаляет прежние изменения.

## Данные и ограничения демо

- SQLite хранится в `data/novichok.sqlite`.
- При запуске сервера синтетический набор создаётся заново; изменения в демо не сохраняются после перезапуска.
- Демо-данные и распределение рисков искусственные. Дашборд скрывает группы меньше пяти человек.
- Система не отправляет сообщения автоматически и не позволяет создавать пользовательские анкеты.
- Форма наставника, ручной ввод посещаемости, импорт CSV и интеграции с внешними сервисами не реализованы.
- Это демо не настроено как production-система для реальных персональных данных.

## Подготовка к размещению в GitHub

`.gitignore` исключает из Git зависимости, собранный клиент, локальную базу данных и `.env`. Перед публикацией проверьте, что в коммит не попали пароли, секреты и реальные персональные данные. Для работы с GitHub клонируйте репозиторий и выполняйте команды запуска из его корневой папки.

## Развёртывание демо на Railway

1. Откройте [Railway](https://railway.com/new) и войдите через GitHub. При запросе доступа проверьте, что подключаете правильный GitHub-аккаунт и репозиторий.
2. Создайте проект через **New Project → GitHub Repository** и выберите `SVERBINSKIY/novichok`.
3. В настройках сервиса задайте:
   - Build Command: `npm install && npm run build`
   - Start Command: `npm start`
   - Healthcheck Path: `/health`
4. В **Variables** добавьте `DEMO_MODE=true` и `NODE_ENV=production`. `PORT` Railway задаёт автоматически. Секрет сессии приложение генерирует случайно при запуске; при желании можно задать свой `SESSION_SECRET` непосредственно в Railway Variables. Не храните его в GitHub.
5. Запустите деплой. В настройках **Networking** нажмите **Generate Domain**, дождитесь статуса **Online** и откройте созданный адрес.
6. Проверьте `/health`, затем главную страницу; демо-входы HR и руководителя доступны без пароля.

Перед запуском проверьте актуальные тарифы и условия Railway. SQLite-файл находится на временной файловой системе платформы и пересоздаётся при запуске сервиса. Это удобно для демо: синтетические данные восстанавливаются, но изменения HR не сохраняются после перезапуска. Не используйте эту конфигурацию для реальных сотрудников или production-нагрузки.
